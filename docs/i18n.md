# Languages

The app is in English or French, the language of the system by default: French when the
system is in French, English otherwise (English is the main language). Préférences › Langue
picks one (System, English, Français); the app restarts in it. Desktop apps: the menu bar of
macOS and the title of the settings window follow (`app_language`).

## How it works

- The texts are written in French in the code, and translated at run time
  (`@angular/localize`, loaded before the app starts: `src/main.ts` → `core/i18n.ts`):
  - templates: `i18n` on the element that holds the text, `i18n-title`, `i18n-aria-label`,
    `i18n-placeholder`… on the attributes;
  - TypeScript: `` $localize`Texte ${valeur}` ``;
  - a text inside an expression (a ternary in a template, a text built in code): the `tr` pipe,
    `('Texte' | tr)` or `('Ouvrir {name}' | tr: { name: x })`, and `tr('Texte')` in code.
- Numbers and dates follow the language (`locale()`: fr-FR or en-GB, 24-hour clock in both).
- `src/locale/en.json`: every text, `{id: {fr, en}}`. `src/locale/en.ts` gives the English
  ones to the app; a text without English stays in French.

## After changing texts

```bash
npm run i18n
```

extracts the texts of the app (`ng extract-i18n`, plus those of `tr`), updates `en.json`, and
lists the texts that have no English yet: write them in `en.json` (keep the `{$…}` placeholders
as they are: they are where the values, links or tags go).

## Adding a language

1. `core/i18n.ts`: the language in `Language`, `LANGUAGES` (its name in its own words) and in
   `systemLanguage()` / `loadLanguage()` / `locale()`;
2. `src/locale/<code>.json` built as `en.json` (copy it, translate the `en` values), and its
   `.ts` like `en.ts`; in `scripts/i18n.mjs`, the same update as for `en.json`;
3. `app.config.ts`: `registerLocaleData` of its locale.
